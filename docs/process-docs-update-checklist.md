# Process Docs Update Checklist

Use this checklist when proposing or applying changes to any process document in docs/.

- [ ] Create an issue using the process doc update template: .github/ISSUE_TEMPLATE/add-update-content-to-process-docs.yml
- [ ] Select the target document (or choose '<new document>') in the template
- [ ] Write a clear summary of the proposed change and rationale
- [ ] Include suggested content and examples where helpful
- [ ] Identify stakeholders and reviewers (PdM, PM, relevant SMEs)
- [ ] Assign an owner and target date for the update
- [ ] Add acceptance criteria (alignment with existing docs, clarity improvement, stakeholder review)
- [ ] Update or create a personas-change-log.md entry describing the change
- [ ] Run a quick consistency check (links, formatting, TOC)
- [ ] Announce the change to stakeholders and update any project README or communication channels
- [ ] Close or link the originating issue and mark acceptance criteria satisfied

Suggested additions for larger updates:
- Add example scenarios or handoff templates
- Add checklists for specific workflows (release, security review, design handoff)
- Schedule a follow-up review to measure the impact of the documentation change
