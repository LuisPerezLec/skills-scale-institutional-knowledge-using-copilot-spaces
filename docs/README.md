# OctoAcme Project Management Documentation

Welcome to the OctoAcme Project Management Docs! This README provides an overview of how projects are run at OctoAcme and contains links to all core process documents.

## Project Management Process Overview

OctoAcme follows a structured, lifecycle-based approach to project management that emphasizes **customer value**, **iterative delivery**, and **clear ownership**. The process flows through five distinct phases:

- **Initiation**: Validating business need and stakeholder alignment to confirm problem statements, success metrics, and resource requirements
- **Planning**: Breaking work into shippable increments with clear acceptance criteria, estimation, and risk/dependency identification
- **Execution & Tracking**: Daily standups, weekly syncs, PR workflows, and embedded quality gates to maintain momentum and visibility
- **Release & Deployment**: Structured releases with pre-release verification, deployment checklists, and incident response playbooks
- **Retrospective & Continuous Improvement**: Regular learning cycles capturing what went well, areas for improvement, and actionable next steps

This phased approach is grounded in core principles of **customer-first thinking**, **data-informed decision-making**, and **psychological safety**, ensuring that teams deliver measurable outcomes while maintaining team morale and a culture of learning.

### Key Characteristics

**Clear Roles & Accountability**
- **Project Manager (PM)**: Owns delivery schedule, risks, and stakeholder communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes the backlog, and measures success
- **Developers**: Implement features and contribute to design, risk identification, and quality
- **QA/Testing**: Validates quality against acceptance criteria and supports release verification

**Quality & Risk Management**
- Pull request workflow with automated CI/CD testing, linting, and security scanning
- Unit tests, integration tests, and end-to-end smoke tests for critical flows
- Risk Register maintained throughout the project with regular review at weekly syncs
- Project board with standardized columns (Backlog, Ready, In Progress, In Review, QA, Done)

**Communication & Coordination**
- Weekly sync between PM and PdM
- Twice-weekly delivery standups
- Clear escalation path: Team-level → PM → Product Lead → Sponsor
- Regular stakeholder updates and release announcements

**Continuous Learning**
- Structured retrospectives after each sprint, release, or significant milestone
- Action items tracked and reviewed in weekly PM syncs
- Iterative process refinement based on team feedback and metrics

## Getting Started

**For New Team Members:**
1. Start with the [Project Management Overview](octoacme-project-management-overview.md) to understand the big picture
2. Read the [Roles and Personas](octoacme-roles-and-personas.md) document to identify your role and responsibilities
3. Review the phase-specific documents as you enter each stage of your project

**For Project Managers:**
- Use the [Project Initiation Guide](octoacme-project-initiation.md) to kickoff new projects
- Refer to [Project Planning](octoacme-project-planning.md) for creating backlog and timelines

**For Product Managers:**
- Start with [Project Initiation Guide](octoacme-project-initiation.md) for defining success metrics
- Use [Project Planning](octoacme-project-planning.md) for prioritization and backlog management
